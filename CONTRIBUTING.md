# Contributing to FormaCMS

Thanks for helping improve FormaCMS.

## Principles

- Keep the project brand-neutral.
- Prefer reusable components and explicit schemas.
- Do not commit real client data, personal secrets, credentials, or service-account files.
- Preserve accessible and responsive behavior.
- Keep public queries separate from private inquiry data.
- Document security implications for changes to authentication, URL handling, or Firestore access.

## Development workflow

1. Open an issue describing the feature or bug.
2. Create a focused branch.
3. Make the smallest coherent change.
4. Run tests, formatting, and relevant security checks.
5. Update documentation and examples.
6. Submit a pull request with behavior and testing notes.

## Suggested checks

- Laravel feature/unit tests
- PHP formatting and static analysis
- Frontend build
- Keyboard navigation and responsive checks
- Authorization tests for every admin route
- Published/draft visibility tests
- Validation tests for external image URLs

## Content and demo data

Use fictional sample content. Do not add real people, customer testimonials, business contact information, financial records, or unverified credentials as defaults.
